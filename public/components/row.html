Component Contract

Row — Full-width section band

The container every page section is built from. The band spans the full viewport width and carries the background colour; the content inside stays on the standard page container, so it lines up with every other section on the page. Its primary use is the Level 2 page hero — copy on one side, image on the other.

Level 2 hero

This is the Row's primary job. A Level 2 section page — a page directly under an L1 landing page — opens with a Row in its split layout: copy on one side, an image on the other. Because it is a Row, the hero sits on the same container as every section beneath it, and the author gets the background tier, rhythm, and measure controls the Hero component doesn't expose.

The four choices an author makes

ChoiceOptionsGuidance
Media sideRight (default) · Left (--split-reverse)Keep one side for a whole L1 branch so the section reads as a set. Reverse re-orders the columns visually only — the heading stays first in the DOM.
RatioEven 50/50 · Text-led 7/5 (--split-text) · Media-led 5/7 (--split-media)Even is the default. Text-led when the lead runs past two lines or there are three actions. Media-led when the photograph carries the message.
BackgroundThe five tiers — see Background coloursGrey and white are the workhorses. Brand blue makes an L2 feel like a campaign; use it for at most one section per L1 branch. The row beneath must use a different tier.
RhythmDefault · Compact · SpaciousSpacious gives an L2 hero more presence without a bigger image. Never --flush.

Rules

  • One split row per page, and it goes first. A second split further down reads as another hero and flattens the page's hierarchy.
  • The heading is the page's <h1>. There is exactly one, and it lives in the hero.
  • The eyebrow names the parent L1 ("Pension solutions", "Members", "Employers"). It is wayfinding, not a kicker — never a slogan.
  • The image is content, not decoration. It goes in a column with a real alt description, which is why the band stays a flat tier and contrast stays provable. Row has no background-image option.
  • Pick one ratio per L1 branch. Mixing 3:2 and 16:9 across sibling L2 pages makes the set look unmaintained.
  • The breadcrumb sits above the hero, in the template's page-header region — not inside the Row. Every L2 page carries one.
  • No --narrow with a split. The narrow measure is for single-column prose; combined with two columns it starves both.

Why there is no half-bleed variant

A common hero pattern runs the image from the text column out to the viewport edge. Row deliberately doesn't offer it: the component's one promise is that content stays on the page container, and a half-bleed breaks that promise for the most prominent element on the page. It also can't hold its alignment — the bleed distance depends on the gap between the container and the viewport, which changes at every breakpoint, so the image edge and the container edge drift apart at exactly the widths where the mismatch is most visible. If a page genuinely needs an edge-to-edge image, that page wants the Hero, which owns the media frame and the scrim tokens that keep text legible over a photograph.

Beige carrying a real page

A tier is easy to approve as a swatch and hard to live with as a page. This is What members get rebuilt from Rows, with its real copy, so beige can be judged against sentences of the length it will actually carry. Beige takes the hero, the benefit card grid, and the resource cards; white takes the rows between them. The label above each row names its classes — green for beige, dark for white.

Open the beige page full screen

Two things this page settles. White cards on beige read warmer and separate more clearly than the same cards on grey, which is the reason to reach for the tier at all. Beige is a neutral, not an accent — it alternates with white exactly the way grey does, and a page that uses it should not also use grey.

Sequencing rules

  • Never repeat a background on adjacent rows. The colour change is the divider. Two grey rows in sequence read as one section with a spacing bug.
  • One or two brand blue rows per page, maximum. Emphasis that repeats stops being emphasis.
  • Nothing goes between rows. No rules, no spacer components, no empty rows.
  • Pick two neutrals per page, not three. White + grey, or white + beige. Alternating three neutrals reads as inconsistency rather than rhythm.
  • Beige and the footer. The footer surface is beige, so a beige row placed last merges into it. End on white, grey, or brand.

5. Content Guidance

  • One idea per row. If a row needs two headers, it's two rows.
  • Header copy stays short. The header slot is capped at 44rem for a readable measure — a title that wraps to three lines is too long.
  • Let the background do the dividing. Alternate white with one neutral down the page, and reserve brand blue for the one or two moments that deserve it.
  • Match the measure to the content. Card grids and tables need the default or wide measure. Running prose needs narrow — full-container body copy is too wide to read comfortably.
  • Give anchored rows a Section ID when the page has in-page navigation, and keep the ID stable — it may already be linked from elsewhere.
  • Rhythm is automatic. Reach for compact or spacious only when the content genuinely calls for it, never to nudge spacing.

  • Author-composed columns use the Bootstrap grid — Row adds no general grid system of its own. The one layout Row defines is --split, a fixed two-slot arrangement for the Level 2 hero.

9. SEO

Row is a structural container with no indexable content of its own — no SEO markup required. It must stay server-rendered so the content it wraps is crawlable, and the heading levels it emits must form a clean document outline, since that outline is what search and AI crawlers read the page structure from.

10. Analytics

Analytics are captured through the shared data-analytics-component attribute on the component root (emitted automatically) and reported to the central data layer. Event names and payloads follow the organisation's standard analytics schema — defined centrally with the analytics team, not invented per component — so no bespoke tracking is specified here. A Row's value to analytics is as the section context for interactions inside it: the Section ID is emitted so child-component events can be attributed to the section they occurred in.

11. AEM Implementation Notes

  • Resource type: caat/components/row. It is a container — cq:isContainer=true — with a responsivegrid child at content.
  • Background, rhythm, and measure are Style System policies, not dialog fields. Authors pick a named option and AEM applies the class. There is no colour picker anywhere in this component.
  • The allowed-components list is enforced by the container policy on the row's responsive grid (its components allow-list), not by author discipline. Keep the policy and the table above in sync.
  • Editable templates lock the page type's structure and leave the row stack open, so authors add and reorder rows but can't change what a row is.
  • Page templates place Navigation, Breadcrumb, and Footer outside the row stack.

14. Definition of Done

  • row.css consumes semantic tokens only — no literal colours or spacing values.
  • All five background tiers ship as Style System options; no colour input is exposed to authors.
  • Contrast verified for body, heading, and muted text on every tier (AA).
  • Container policy enforces the allowed-components list; excluded components are rejected in the editor.
  • Brand-tier guard blocks Tables, Forms, Data Visualization, and Alerts.
  • Adjacent-background and brand-budget validation wired to author-facing messages.
  • Row emits a named landmark and a valid heading outline.
  • Geometry matches .caat-section — a Row and a hand-authored section on the same page line up exactly.
  • Split layout ships with both sides and all three ratios; media composes the Image component rather than a bespoke media block.
  • Split stacks heading-first below 992px on both sides, and the <h1> leads the DOM.
  • L2 template policy: split Row locked as the first component; Hero excluded from L2 templates and Row-split excluded from L0/L1.
  • QA checklist signed off at mobile, tablet, and desktop.
