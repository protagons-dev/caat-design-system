1. Component Summary

Component nameHero
AEM component namecaat/components/hero
Recommended implementationCustom component — no Core Component equivalent exists for this design
Component groupCAAT Design System
PurposeOrient visitors, present one clear message and CTA on key landing pages
Existing AEM component replacedCAAT Carousel (#5) — consolidate rotating hero into single-message hero

Primary use cases

  1. Homepage hero — primary brand statement and CTA
  2. Campaign landing pages — single focused message
  3. Pension solutions pages — orient visitors to key offering
  4. Employer acquisition pages — value proposition for prospective employers
  5. Event registration pages — promote upcoming events

Non-goals

  1. Not for every page — use breadcrumb/title pattern instead for interior pages
  2. Not for multiple competing CTAs — one primary CTA only
  3. Not for embedding forms — use a dedicated form component below the hero
  4. Not for logo placement — the hero is for messaging, not branding

Hero card overhang

The card overhang (the amount the card extends below the hero media) must never exceed 75 px. This is enforced via the CSS custom property --caat-hero-card-overhang: 75px.

Visual variants

  • Standard — full-size hero with card overlaid on media
  • With stats strip — standard hero with an attached stat bar below the image
  • Full-width breakout — hero breaks out of container to span full viewport width

Photography support

Photography backgrounds use a subtle gradient overlay to ensure text readability. Apply the image via the --hero-image custom property or use the pre-built .gradient-demo class for abstract gradients.

4. Authoring Validation Rules

  1. Heading is required. The dialog must not allow saving without it.
  2. CTA label and CTA URL are required together — if one is provided, the other must be as well.
  3. Image alt text is required unless the "Decorative image" checkbox is enabled.
  4. Eyebrow text must not exceed 3 words. Display a validation warning if exceeded.
  5. Summary must not exceed 35 words. Display a character/word count indicator.
  6. Only one primary CTA is permitted. The dialog does not allow adding multiple CTA buttons.

5. Content Guidance

Heroes orient visitors quickly, preserve the image's focal point, and keep the CTA usable on mobile. Use them for page introductions, campaign landing pages, and major story moments — not for every content block.

Recommended text length

ElementGuideline
Eyebrow1–3 words
Headline6–12 words, ideally under two lines on desktop
Summary18–35 words
CTA label2–5 words, starting with a verb

Image safe zones

  • Keep faces, logos, text, and key details out of the overlay zone (left third of image).
  • Use centre-right crops when the content card sits left.
  • Test desktop, tablet, and mobile before publishing.

Mobile behaviour

  • Stack the card below the image on narrow viewports.
  • Reduce image height before reducing legibility.
  • Avoid placing small text inside the image itself.

Busy images or people

  • Add a subtle gradient overlay only when needed for readability.
  • Choose images with quiet negative space for the card area.
  • Never cover a person's face, logo, or meaningful action with the headline or CTA.

Strong hero usage

"A retirement solution where everyone wins"

Why it works: concise message, one audience need, calm visual field, clear next step, and no meaningful image detail hidden under the card.

Weak hero usage

"Learn more about all of our services and programs today"

Why it fails: vague promise, no audience, too many possible actions, and a busy image that competes with the message.

7. CSS Contract

The hero component relies on the global token layer defined in /assets/css/tokens.css. All component-specific styles live in /assets/css/components/hero.css.

Core classes

.caat-composable-hero   /* Root wrapper */
.caat-hero-frame        /* Positioning context for card overlay */
.caat-hero-media        /* Background image / gradient area */
.caat-hero-card         /* Overlay card — LAYOUT (size/position) */
.caat-hero-panel        /* Overlay card — SKIN (canonical, caat-base.css);
                           compose BOTH classes on the card element */
.accent-rule            /* Green divider bar */

/* Variants */
.caat-hero-slight-overlap   /* Card positioned at bottom of image */

/* Stat strip */
.caat-stat-strip           /* Full-width stats bar */
.caat-stat-item            /* Individual stat */

75 px overhang rule

.caat-hero-slight-overlap {
  --caat-hero-card-overhang: 75px;
}
.caat-hero-slight-overlap .caat-hero-frame {
  padding-bottom: var(--caat-hero-card-overhang);
  overflow: visible;
}

Responsive stacking

At 992 px and below, the hero card unstacks from the overlay position and sits below the media area. The overhang is reduced to 56 px on tablet breakpoints.

Composition & behaviour notes

The hero is static — no JavaScript. Everything below is CSS composition; verify it survives AEM integration.

  • Panel skin vs layout: the card element composes two classes — .caat-hero-card (size/position, hero.css) + .caat-hero-panel (canonical glass skin incl. hover lift, caat-base.css). Omitting the panel class yields an unstyled box; omitting the card class loses positioning.
  • Media: the image fills .caat-hero-media with object-fit: cover; min-heights step down 22 → 18 → 14 rem across breakpoints. Author images for the worst crop (centre-weighted focal point) — there is no focal-point control.
  • Legibility scrim: .caat-hero-media::after applies var(--caat-overlay-side). Never remove it when text or the panel sits over a photo; it is the contrast guarantee.
  • Stat strip: composes the Stat/KPI component (.caat-stat-strip / .caat-stat-item, stat.css) — hero.css adds only the rounded bottom corners. Author stats through the Stat component contract.
  • Interactivity: the panel lifts on hover (decorative). If the whole card is made clickable, use a stretched link inside it — the panel then shows the focus ring via the Card/panel :has(.stretched-link:focus-visible) pattern; CTAs inside the panel use the Button contract (incl. --outline-white on the glass surface).
  • Reduced motion: the lift/transition is neutralized globally by the prefers-reduced-motion rule in caat-base.css — no per-component handling needed.
Note: Do not duplicate token values inside the component CSS. Always reference the custom property (e.g. var(--caat-blue-900)) so that theme changes propagate automatically.

8. Accessibility Requirements

RequirementAcceptance criteria
Keyboard focus on CTA The CTA link must be reachable via Tab and activatable with Enter. A visible focus ring (var(--caat-focus)) must appear on :focus-visible.
Meaningful image alt Content images must have descriptive aria-label on the .caat-hero-media element with role="img".
Decorative image handling When the image is decorative, set role="presentation" and aria-hidden="true". Do not output an empty aria-label.
Heading level configurable Authors must be able to set the heading level (h1–h3) to maintain correct document outline. Use h1 only when this is the page hero.
Sufficient contrast on card overlay White text on the card background must meet WCAG 2.1 AA (4.5 : 1 for normal text, 3 : 1 for large text). The default #003750 background passes.
No auto-playing carousel This component deliberately replaces the carousel. It must not auto-rotate, auto-advance, or include multiple slides.

9. SEO Requirements

  1. Heading level is configurable — use <h1> only when this hero is the page-level hero. Interior sections should use <h2> or <h3>.
  2. Descriptive CTA text — avoid generic labels like "Learn more". Use action-oriented, context-rich text (e.g. "Explore pension solutions").
  3. Real href on CTA link — the CTA must be a real <a> element with a crawlable href. Do not use JavaScript-only navigation.
  4. Don't use background-image for content images — if the image conveys meaning, render it as an <img> element or use role="img" with aria-label so the content is accessible to search engines and assistive tech.

10. Analytics Requirements

Analytics are captured through the shared data-analytics-component attribute on the component root (emitted automatically) and reported to the central data layer. Event names and payloads follow the organisation's standard analytics schema — defined centrally with the analytics team, not invented per component — so no bespoke tracking is specified here.

11. AEM Implementation Notes

Existing component mapping

This component replaces CAAT Carousel (component #5) in the existing AEM component library. The recommendation is to consolidate the rotating hero carousel into a single-message hero for better usability, accessibility, and performance.

AEM triage

New component No direct AEM Core Component equivalent exists. Build as a custom component with HTL/Sightly.

Proxy / extend guidance

There is no Core Component to proxy. Create a custom component at /apps/caat/components/hero. Build the HTL template (hero.html) to emit the semantic HTML defined in Section 6. Use data-sly-attribute for dynamic class and data-attribute output.

Client library structure

  • Category: caat.components.hero
  • Dependencies: caat.base (tokens + base styles)
  • CSS: hero.css
  • JS: hero.js (analytics wiring, impression observer)

Stats strip

The stats strip can be implemented as either a child component within the hero or as a separate stand-alone component (caat/components/stat-strip) placed immediately below the hero in the page template. The recommended approach is a separate component for maximum reusability.

13. QA Acceptance Checklist

  • The hero card overhang does not exceed 75 px in the slight-overlap variant at any viewport width.
  • The hero card stacks below the media image at 992 px and below (responsive stacking).
  • Image safe zone testing: text on the card remains legible with various photography crops and positions.
  • CTA focus ring is visible and meets WCAG 3 : 1 contrast ratio against the card background.
  • The hero renders correctly at desktop, tablet, and mobile viewports with expected spacing and sizing.
  • Analytics data attributes are present in the DOM and the cta_click event fires correctly on CTA interaction.
